## What the application tests establish

The tests operate on the built `dist/` under `/screenshot-stitch/`, not the Vite development server or a separate HTML mockup. They import real screenshots, check rejection and reordering, run genuine pixel overlap and Tesseract OCR, select/move/resize/manual-edit masks, toggle styles, compare, undo/redo, and save a newly encoded PNG. Download assertions inspect PNG bytes and expected dimensions. Manual seam tests rebuild with an explicit overlap, reopen it, and restore the automatic result.

The real demo is generated from synthetic content and passes through the same stitching, OCR, QR and redaction pipeline as uploads. Detections are not pre-seeded. Failure tests explicitly abort OCR asset requests; the stitch remains usable for manual editing. Cancellation rejects stale results. The main application flow asserts no page errors, no third-party HTTP requests, no HTTP write methods, and correct project-prefixed model URLs.

The native engine tests verify exact seam pixels, duplicate handling, repeated chrome preservation, format validation, fallback behavior, worker execution, solid-mask coverage and ordering, fractional export scales, alpha flattening, private PNG metadata stripping, and malformed-geometry rejection. Their same-origin isolated fixture allows blob-imported test modules; the separate bundled-app tests retain and exercise the production CSP.

The earlier release candidate's module-worker restrictions are resolved on this VPS. Historical RC reports in the source handoff are not the current release results.

## Visual captures

`node scripts/capture-release.mjs` records the real production application at 1440×1080 and 390×844 viewports, including full scrollable pages. Captures show upload, preparation, genuine stitching/scan states, review, notes, comparison, precise mask controls, pixelation, blur, manual redactions, seam editing, export warnings, final export/review, save success, privacy, shortcuts and reset confirmation. Local worker asset delivery is briefly delayed only to capture short-lived loading states; OCR results are never fabricated. Forty screen images and their manifest are in the release gallery on the build machine.

## Scope and remaining platform checks

No physical phone was attached. Real OS share sheets, platform clipboard permissions, low-memory behavior, and tactile touch feel still depend on the user's browser/device; browser emulation is not physical-device certification. No GitHub repository was supplied, so this work did not publish to a live GitHub Pages URL. The actual static project-prefix deployment path is covered by tests, and the workflow is included.

Automatic detection can miss names, photos, codes, addresses or other details. OCR is English. Face detection depends on an available browser-native detector. Use solid masks for actual secrets and inspect the entire image before export. No finite test suite is a guarantee of confidentiality, perfect overlap detection or absence of every defect.

## Reproduce

```sh
npm ci
npx playwright install --with-deps chromium webkit
npm audit --audit-level=moderate
npm run verify
```

`npm run verify` typechecks, runs Vitest, builds the static site, and runs the browser suites. The release workflow does not deploy when those gates fail. Reports and logs contain only synthetic test content.
