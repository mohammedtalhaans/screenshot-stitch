## Browser compatibility detail

Chromium exercised actual stitch/export module workers. This Windows WebKit build does not expose OffscreenCanvas, so the app exercised its canvas compatibility paths, including the added QR/barcode fallback. Three worker-only engine subcases are explicitly recorded as unsupported in the WebKit attachment; the canvas/fallback and application flows still ran. The 39 figure counts top-level Playwright tests, not each internal pixel subcase. This is not a claim of physical iPhone testing.

Diagnostic comparison found that WebKit PNG/canvas round trips can change some source RGB channels by exactly one level. Source-pixel comparisons allow that bounded RGB difference while requiring exact alpha and dimensions. Every covered solid-mask pixel still must equal the exact opaque mask color; those assertions passed.

## Practical limits

This release is prepared for GitHub Pages but has not been deployed to a user repository. Verify the demo-to-download flow on the final live URL after deployment. Clipboard and native sharing are browser/device capabilities; the common verified handoff is PNG download. Use vertical screenshots from the same app, width and zoom. OCR is English, suggestions can miss details, and solid masks should be used for secrets. Always inspect the entire final image.
